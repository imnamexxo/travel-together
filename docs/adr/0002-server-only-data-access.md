# 앱은 DB에 직접 접근하지 않고 모든 데이터 요청은 FastAPI를 거친다

Supabase를 쓰지만, 앱은 Supabase Auth로 로그인만 하고 데이터와 이미지 요청은 모두 FastAPI 서버로 보낸다. 서버는 서비스 키로 DB와 Storage에 접근하고, 클라이언트에 대한 RLS는 전부 거부(deny-all)로 둔다. 이미지는 서버가 권한을 확인한 뒤 짧은 만료의 서명 URL로 내준다. 권한 규칙(총무만 지출·송금 수정, 멤버는 본인 사진·경로만 삭제 등)을 서버 한 곳에만 두어야 검증하기 쉽기 때문이다. 앱에서 Supabase를 직접 조회하도록 "단순화"하면 RLS와 서버 양쪽에 같은 규칙이 생기므로 피한다.

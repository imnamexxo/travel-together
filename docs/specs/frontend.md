# [Frontend] 여행 앱 모바일 앱 스펙

## Problem Statement

친구들과 국내 여행을 가면 계획은 메신저 대화방에, 사진은 각자의 휴대폰에, 지출은 총무의 메모에 흩어진다. 계획을 짜는 일은 한두 사람에게 몰리고, 여행이 끝나면 어디를 어떻게 다녔는지, 그곳에서 무엇을 찍고 얼마를 썼는지를 다시 맞추기 어렵다. 공동 지출은 공동 품목·일부 인원 품목·개인 물품이 섞여 있어 정확히 나누기 번거롭다.

멤버들은 휴대폰 하나로 함께 계획하고, 사진으로 기록하고, 정산까지 끝낼 수 있는 앱이 필요하다.

## Solution

React Native·Expo·TypeScript 모바일 앱. 하단 탭은 플래너·앨범·지도·정산 네 개다.

- 이메일+비밀번호로 가입·로그인하고, 여행을 만들거나 초대 코드로 들어간다.
- 플래너에서 날짜별 일정 항목을 함께 편집하고, AI 추천 일정 중 마음에 드는 것만 골라 넣는다. 장소가 확인되지 않은 추천은 "확인 필요"로 보인다.
- 앨범에 사진을 올리면 앱이 휴대폰 안에서 촬영 위치로 일정의 장소를 찾아 붙인다. 위치 좌표는 서버로 보내지 않는다.
- 지도에서 들른 곳과 계획만 한 곳을 핀으로 구분해 보고, 핀을 누르면 그곳의 일정·사진·지출을 본다.
- 총무는 영수증을 찍어 지출 초안을 받고, 원본을 보며 품목과 분담 대상을 확인한 뒤 확정한다. 멤버들은 자기 잔액, 송금 제안, 부담액의 근거를 본다.

모든 데이터는 서버 API를 통해서만 주고받는다(ADR-0002). 서버 동작은 백엔드 스펙(#1)을 따른다.

## User Stories

### 시작과 여행

1. 사용자로서, 이메일과 비밀번호로 가입하고 싶다.
2. 사용자로서, 앱을 다시 열어도 로그인이 유지되길 원한다.
3. 사용자로서, 로그아웃하고 싶다.
4. 사용자로서, 내가 멤버인 여행 목록을 보고 하나를 열고 싶다.
5. 사용자로서, 여행 이름과 시작일·종료일을 정해 새 여행을 만들고 싶다.
6. 사용자로서, 초대 코드를 입력해 여행에 들어가고 싶다.
7. 사용자로서, 초대 코드를 입력할 때 대소문자나 헷갈리는 문자(0/O, 1/I) 때문에 실패하지 않길 원한다.
8. 사용자로서, 코드가 틀렸거나 무효이거나 여행이 꽉 찼을 때 이유를 알고 싶다.
9. 총무로서, 초대 코드를 보고 복사·공유하고 싶다, 그래야 메신저로 친구들에게 보낼 수 있다.
10. 총무로서, 초대 코드를 재발급하고 싶다.
11. 멤버로서, 여행의 멤버 목록과 누가 총무인지 보고 싶다.
12. 총무로서, 여행 이름과 기간을 고치고 싶다.
13. 총무로서, 기간을 줄였다가 거절되면 어느 날짜의 일정 항목 때문인지 알고 싶다.
14. 멤버로서, 여행에서 나가고 싶고, 나갈 수 없다면 그 이유를 알고 싶다.
15. 총무로서, 확인 창을 거쳐 여행을 삭제하고 싶다, 그래야 실수로 모두의 사진을 지우지 않는다.

### 여행 홈과 플래너

16. 멤버로서, 여행 홈에서 날짜별 일정 타임라인을 보고 싶다.
17. 멤버로서, 여행 중에는 오늘 일정이 강조되길 원한다.
18. 멤버로서, 각 일정 항목에 연결된 사진 수와 지출 금액을 작게 보고 싶다.
19. 멤버로서, 일정 항목을 추가·수정하고 싶다(시간, 장소, 메모, 예상 비용).
20. 멤버로서, 일정 항목에 붙일 장소를 키워드로 검색해 고르고 싶다.
21. 멤버로서, 장소 없이 "자유시간" 같은 일정 항목도 만들고 싶다.
22. 멤버로서, 하루 안에서 일정 항목 순서를 바꾸고 싶다.
23. 멤버로서, 내가 만든 일정 항목을 지우고 싶다(총무는 모든 일정 항목).
24. 멤버로서, 다른 멤버가 바꾼 내용을 화면에 다시 들어오거나 당겨서 새로고침할 때 보고 싶다.

### 추천 일정

25. 멤버로서, 여행지·기간·취향(예: 맛집 위주, 여유로운 일정)을 입력해 추천 일정을 받고 싶다.
26. 멤버로서, 추천을 기다리는 동안 진행 중임을 알고 싶다.
27. 멤버로서, 추천 일정을 날짜별 카드로 보고 싶다.
28. 멤버로서, "확인 필요" 카드를 한눈에 구분하고 싶다.
29. 멤버로서, 카드를 여러 개 골라 "플래너에 추가"하고 싶다.
30. 멤버로서, 추가한 뒤 플래너로 돌아가 결과를 바로 보고 싶다.
31. 멤버로서, 하루 추천 횟수를 다 쓰면 그렇다는 안내를 받고 싶다.
32. 멤버로서, 추천이 실패하면 직접 일정을 쓰도록 안내받고 싶다.

### 앨범

33. 멤버로서, 휴대폰 앨범에서 여러 장을 골라 올리고 싶다.
34. 멤버로서, 앱에서 바로 사진을 찍어 올리고 싶다.
35. 멤버로서, 올리기 전에 사진이 자동으로 줄어들어 데이터와 시간을 아끼고 싶다.
36. 멤버로서, 업로드 진행 상황과 실패한 사진을 보고, 실패한 것만 다시 올리고 싶다.
37. 멤버로서, 사진을 날짜별·장소별로 보고 싶다.
38. 멤버로서, 올린 사람으로 사진을 거르고 싶다.
39. 멤버로서, 사진을 크게 보고, 연결된 장소와 일정 항목을 보고 싶다.
40. 멤버로서, 사진의 장소 연결을 바꾸거나 해제하고 싶다.
41. 멤버로서, 내 사진을 지우고 싶다(총무는 모든 사진).
42. 멤버로서, 여행 사진이 200장에 가까워지면 남은 장수를 알고 싶다.

### 지도

43. 멤버로서, 지도에서 이 여행의 장소를 핀으로 보고 싶다.
44. 멤버로서, 들른 곳(사진·지출이 연결된 곳)과 계획만 한 곳을 핀 모양으로 구분하고 싶다.
45. 멤버로서, 날짜를 골라 그날 들르거나 계획한 곳만 보고 싶다.
46. 멤버로서, 특정 멤버가 사진을 올리거나 결제한 곳만 보고 싶다.
47. 멤버로서, 핀을 누르면 그곳의 일정 항목·사진·지출을 하단 시트에서 보고 싶다.
48. 멤버로서, 지도를 열 때 핀이 모두 보이도록 화면이 맞춰지길 원한다.
49. 멤버로서, 앱이 내 위치 권한을 요구하지 않길 원한다.
50. 멤버로서, 사진을 올릴 때 위치 정보가 서버로 가지 않는다는 안내를 보고 싶다.
51. 멤버로서, 사진 상세에서 장소를 검색해 직접 연결하고 싶다, 그래야 일정에 없던 곳도 지도에 남는다.
52. 멤버로서, 장소에 연결되지 않은 사진이 몇 장인지 보고 연결하러 갈 수 있길 원한다.
53. 멤버로서, 지도에서 아직 들르지 않은 계획 장소를 보고 다음 행선지를 고르고 싶다.

### 지출(총무)

54. 총무로서, 영수증을 찍거나 앨범에서 골라 지출 초안을 받고 싶다.
55. 총무로서, 분석 중임을 알고, 실패하면 직접 입력으로 이어가고 싶다.
56. 총무로서, 영수증 원본과 추출된 품목을 나란히(또는 전환하며) 비교하고 싶다.
57. 총무로서, 비어 있는 값을 눈에 띄게 보고 채우고 싶다.
58. 총무로서, 품목을 추가·수정·삭제하고 싶다.
59. 총무로서, 결제자를 고르고 싶다.
60. 총무로서, "누가 함께 썼나요?" 화면에서 기본 분담 대상을 한 번 고르고, 예외 품목만 멤버 버튼을 눌러 바꾸고 싶다.
61. 총무로서, 품목 금액 합과 총액이 다르면 바로 보고 싶다.
62. 총무로서, 확정할 때 깨진 조건이 있으면 어느 품목의 무엇이 문제인지 보고 싶다.
63. 총무로서, 추천된 장소 후보 중 하나를 고르거나 비워 두고 싶다.
64. 총무로서, 영수증 없이 지출을 직접 입력하고 싶다.
65. 총무로서, 확정된 지출도 고치거나 지우고 싶다.
66. 총무로서, 확인이 필요한 지출(초안·검사 실패)을 한곳에 모아 보고 싶다.
67. 일반 멤버로서, 지출과 영수증을 볼 수 있지만 수정 버튼은 보이지 않길 원한다.

### 정산

68. 멤버로서, 정산 탭 맨 위에서 내가 받을 금액 또는 보낼 금액을 크게 보고 싶다.
69. 멤버로서, 내 결제액과 부담액을 함께 보고 싶다.
70. 멤버로서, 송금 제안을 카드로 보고 싶다("준호 → 민지 8,500원").
71. 멤버로서, 내 부담액이 어느 지출의 어느 품목에서 왔는지 근거 화면을 보고 싶다.
72. 총무로서, 송금 제안 카드에서 "송금 완료로 기록"을 누르고 싶다.
73. 총무로서, 일부만 송금된 경우 금액을 직접 입력해 기록하고 싶다.
74. 총무로서, 잘못 기록한 송금을 지우고 싶다.
75. 멤버로서, 기록된 송금 목록을 보고 싶다.
76. 멤버로서, 지출이 바뀐 뒤 송금 제안이 바뀌면 최신 결과를 보고 싶다(재정산).
77. 멤버로서, 모든 잔액이 0이면 "정산 완료"를 보고 싶다.
78. 멤버로서, 실제 송금은 은행 앱에서 한다는 안내를 보고 싶다.
79. 멤버로서, 송금 안내문을 복사해 메신저에 붙이고 싶다.

### 공통

80. 사용자로서, 서버 오류나 네트워크 끊김 때 무엇이 실패했는지와 다시 시도할 방법을 알고 싶다.
81. 사용자로서, 로그인이 만료되면 로그인 화면으로 돌아가고 싶다.
82. 사용자로서, 총무만 할 수 있는 동작은 일반 멤버에게 보이지 않길 원한다.

## Implementation Decisions

### 구조

- Expo(React Native) + TypeScript, 파일 기반 라우팅(현재 템플릿의 expo-router 구조를 이어 씀). 기존 템플릿 화면(home/explore 예제)은 걷어낸다.
- 지도(react-native-maps의 구글 지도 키)와 실기기 검증을 위해 EAS 개발 빌드로 실행한다. 프로젝트 초기에 개발 빌드 환경(Android 우선)을 만든다. 앱은 기기 위치 권한을 요청하지 않는다(ADR-0003).
- **API 클라이언트 모듈**: 화면은 이 모듈만 통해 서버와 통신한다. 로그인 토큰 첨부, 공통 오류 형식 해석(코드·메시지·세부 목록), 401 시 로그아웃 처리, 지출 생성·영수증 업로드의 멱등 키 생성을 이 모듈이 맡는다. 서버의 자원(여행, 멤버, 초대 코드, 장소 검색, 일정 항목, 추천 요청·채택, 사진, 영수증, 지출·확정, 장소 후보, 정산 결과, 송금, 지도)마다 타입이 있는 함수를 제공한다. 테스트에서는 이 모듈 전체를 가짜로 바꾼다.
- **인증**: Supabase JS SDK는 이메일+비밀번호 가입·로그인·세션 유지에만 쓴다. Supabase DB나 Storage를 앱에서 직접 부르지 않는다(ADR-0002).
- **현재 여행과 내 역할**: 여행을 열면 내 멤버 정보(총무 여부 포함)를 불러와 화면 전역에서 쓴다. 총무 전용 동작은 이 값으로 숨긴다(서버도 다시 막는다).
- **서버 데이터 상태**: 화면 진입과 당겨서 새로고침 때 다시 불러온다. 실시간 동기화는 하지 않는다.

### 기술 스택 보강 (2026-10-28)

- **서버 데이터 관리**: TanStack Query로 서버 데이터를 불러오고 캐시한다. 화면 진입 시 다시 불러오기, 당겨서 새로고침, 로딩·오류 상태, 재시도를 여기에 맡긴다. 변경 요청 후에는 관련 데이터를 무효화해 다시 불러온다.
- **API 타입**: openapi-typescript로 서버의 OpenAPI 명세에서 TypeScript 타입을 생성하고, API 클라이언트 모듈은 이 타입만 쓴다. 서버 API가 바뀌면 타입을 다시 생성한다.

### 기능별 결정

- **초대 코드 입력**: 입력값을 대문자로 바꾸고 공백을 지운다. 0/O/1/I는 코드 문자 집합에 없으므로, 입력 시 O→0 같은 자동 치환은 하지 않고 서버 판정을 따른다.
- **사진 업로드**: expo-image-picker(앨범·카메라)로 고르고, 업로드 전에 앱에서 긴 변 1600px JPEG로 줄인다. 줄이기 전에 원본 EXIF에서 촬영 시각과 GPS를 읽는다. GPS가 있으면 휴대폰 안에서 같은 날 일정 항목의 장소 중 300m 안의 가장 가까운 곳을 찾아 그 장소 id만 보낸다. 줄인 파일에는 EXIF를 남기지 않고, GPS 좌표는 어디에도 보내거나 저장하지 않는다. iOS에서 위치가 빠진 사진은 장소 없이 보낸다. 여러 장은 순서대로 올리고, 장별로 성공/실패를 표시해 실패한 것만 다시 올린다.
- **지도**: react-native-maps. Android는 구글 지도 API 키를 앱 설정에 넣는다. 장소 핀을 들른 곳/계획만 한 곳 두 모양으로 그리고, 선은 그리지 않는다. 핀을 누르면 하단 시트에 그 장소의 일정 항목·사진 썸네일·지출 요약을 보여준다. 기기 위치 권한과 "내 위치" 표시는 쓰지 않는다.
- **추천 일정 화면**: 결과 카드에 "확인 필요" 배지를 붙이고, 체크한 카드만 채택 요청에 보낸다.
- **지출 편집**: 상단에 영수증 원본(확대 가능), 아래에 품목 목록. 각 품목 아래에 멤버 버튼(선택 시 강조와 체크 표시)을 두고, 지출 상단의 "기본 분담 대상"을 바꾸면 예외로 바꾸지 않은 품목에 반영한다. 품목 합과 총액의 차이를 항상 보여준다. 확정 실패 시 서버가 준 깨진 조건 목록을 해당 품목 옆에 표시한다.
- **정산 화면**: 서버가 계산한 결과만 그린다. 앱에서 금액을 다시 계산하지 않는다.
- **금액 표시**: 원 단위 정수를 천 단위 쉼표와 "원"으로 표시한다.

## Testing Decisions

- 좋은 테스트는 사용자가 보는 것과 하는 것만 검증한다. 화면을 그리고, 버튼을 누르고, 보이는 글자와 API 클라이언트로 나간 요청을 확인한다. 컴포넌트 내부 상태, 훅 호출 순서, 스타일은 검증하지 않는다.
- **경계 3 — API 클라이언트 모듈**: 테스트에서는 API 클라이언트를 가짜로 바꾸고, React Native Testing Library로 핵심 화면 흐름을 검증한다.
  - 품목별 분담: 기본 분담 대상 선택 → 예외 품목 변경 → 저장 요청에 올바른 분담 대상이 실림
  - 확정 실패: 서버가 깨진 조건을 돌려주면 해당 품목 옆에 표시됨
  - 추천 일정: "확인 필요" 표시, 고른 카드만 채택 요청에 실림
  - 총무가 아니면 지출·송금 수정 버튼이 보이지 않음
  - 초대 코드 입력 정규화와 오류 메시지
  - 정산 화면: 서버 결과대로 받을/보낼 금액과 송금 제안 카드가 그려짐, 총무의 "송금 완료로 기록"이 올바른 송금 요청을 보냄
  - 사진 업로드: 일부 실패 시 실패한 사진만 다시 시도
- **경계 4 — 실기기 수동 검증**: 자동 테스트로 확인하기 어려운 것은 체크리스트로 Android 실기기(가능하면 iOS도)에서 확인한다.
  - 카메라·앨범 권한, EXIF 위치 유무에 따른 자동 연결, 업로드된 파일에 EXIF가 없는지 확인
  - 앱이 위치 권한을 요청하지 않는지 확인
  - 지도 렌더링, 들른 곳/계획만 한 곳 핀 구분, 핀 하단 시트
  - 개발 빌드에서 배포 서버와 전체 흐름(가입 → 여행 → 플래너·추천 → 사진 → 지출 → 정산 → 지도)
- **선행 사례**: 프론트엔드에 테스트가 아직 없다. 이 스펙이 jest-expo와 React Native Testing Library 구성, 가짜 API 클라이언트 주입 방식을 처음 만든다.

## Out of Scope

- 서버 구현(백엔드 스펙 #1)
- 실시간 동기화, 플래너 실시간 공동 편집
- GPS 이동경로 기록, 친구 현재 위치 공유, 기기 위치 권한 사용(ADR-0003)
- 앨범 영상·댓글·좋아요
- 직접 금액 분담, 수량 비례 분담
- 실제 송금·계좌 연동, 복수 통화
- 소셜 로그인, 총무 위임
- 웹 버전 지원(템플릿의 웹 전용 파일은 유지하되 대상 아님)
- 앱 이름·아이콘·스토어 배포(이름 미정)

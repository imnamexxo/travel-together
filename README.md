# 공동 여행 관리 앱 — travel-together

친구들과 여행을 함께 계획하고, 사진을 공유하며, 여행 중 지출을 정산하는 모바일 앱입니다.

장소를 중심으로 일정·사진·지출을 연결하여 여행 전 계획부터 여행 후 기록까지 하나의 여행 안에서 관리하는 것을 목표로 합니다.

## 1. MVP 구현 계획 — SP2 구현 범위

### 구현 목표

SP2에서는 실제 모바일 기기에서 여행을 만들고, AI 추천 또는 직접 입력으로 일정을 작성한 뒤, 멤버들과 사진을 공유할 수 있는 핵심 흐름을 구현합니다.

각 기능은 배포 서버와 연결하며, 앱을 다시 실행해도 저장한 데이터를 조회할 수 있도록 합니다.

### 구현 기능

| 기능 | 구현 내용 | 완료 기준 |
|---|---|---|
| 회원가입·로그인 | Supabase Auth를 활용한 이메일·비밀번호 인증과 로그인 상태 유지 | 두 개의 계정으로 각각 로그인하고 본인의 여행 조회 |
| 여행 생성·참여 | 여행명·기간을 입력하여 여행 생성(만든 사람이 총무), 초대 코드로 멤버 참여 | 초대한 멤버가 같은 여행의 일정과 사진 조회 |
| 날짜별 공유 플래너 | 일정 항목의 시간·장소·메모·예상 비용 등록 및 권한에 따른 수정·삭제 | 저장한 일정이 날짜순으로 표시되고 다른 멤버가 새로고침 후 확인 |
| 장소 검색 | 카카오 로컬 API로 장소 검색 및 이름·주소·좌표 저장, 같은 곳은 장소 하나로 재사용 | 검색 결과를 선택하여 일정에 장소 연결 |
| AI 일정 추천 | 여행지·기간·취향을 입력받아 Gemini API로 날짜별 추천 일정 생성 | 추천 결과 중 사용자가 선택한 항목만 플래너에 추가 |
| 추천 장소 확인 | AI가 추천한 장소를 카카오 로컬 API 검색 결과와 대조 | 검색 결과와 일치하지 않는 장소에 확인 필요 표시 및 직접 수정 제공 |
| 공유 사진 앨범 | 사진 압축·위치 정보(EXIF) 제거·업로드·조회 및 권한에 따른 삭제 | 한 멤버가 올린 사진을 다른 멤버가 조회 |
| 사진과 장소 연결 | 휴대폰 안에서 촬영 위치로 가까운 일정 장소에 자동 연결(좌표는 서버로 보내지 않음), 장소 검색으로 직접 연결·수정 | 일정 상세 화면에서 연결된 사진 조회 |
| 기본 권한 및 서버 배포 | 서버에서 인증·여행 참여 여부·수정 권한 확인 | 다른 여행의 데이터 접근을 차단하고 실제 기기에서 배포 서버 이용 |

### SP2 시연 시나리오

1. 사용자 A가 회원가입 후 여행을 만듭니다.
2. 사용자 B가 초대 코드를 입력하여 같은 여행에 참여합니다.
3. 여행지·기간·취향을 입력하여 AI 일정 추천을 받습니다.
4. 추천 장소를 확인하고 선택한 항목을 플래너에 추가합니다.
5. 멤버가 일정을 수정하면 다른 멤버가 새로고침하여 변경 내용을 확인합니다.
6. 사진을 업로드하면 촬영 위치가 가까운 일정 장소에 자동으로 연결됩니다.
7. 다른 멤버가 해당 일정과 연결된 사진을 조회합니다.

### RISK 관리 계획

| 위험요소 | 예상 영향 | 대응 계획 |
|---|---|---|
| AI가 부정확한 장소 또는 일정을 추천 | 실제 방문이 어려운 일정 생성 | 추천을 초안으로 제공하고 장소 검색 결과와 대조, 사용자가 확인한 항목만 저장 |
| Gemini API 지연·오류·호출 제한 | AI 일정 생성 불가 | 실패 상태와 재시도 제공, 직접 일정 작성으로 기본 이용 흐름 유지, 여행별 하루 호출 횟수 제한 |
| 장소 검색 API 오류 | 장소 검색 및 좌표 저장 불가 | 장소 없이 메모로 일정 작성 허용, 장소가 없는 일정은 지도 표시 대상에서 제외 |
| 사진 업로드 실패·저장 용량 증가 | 앨범 이용 지연 및 비용 증가 | 업로드 전 압축, 파일 형식·크기·사진 수 제한, 실패한 사진만 재시도 |
| 여러 멤버의 동시 일정 수정 | 다른 멤버의 수정 내용 덮어쓰기 | 마지막으로 저장한 내용을 반영하고, 화면 진입·새로고침 시 최신 내용을 다시 불러옴 |
| 인증·권한 처리 오류 | 다른 여행 데이터 조회 또는 무단 수정 | 서버에서 요청마다 권한 검사, 비회원·다른 여행·일반 멤버 계정으로 접근 검증 |
| 개발 일정 지연 | SP2 핵심 흐름 미완성 | 여행·플래너·앨범의 기본 저장·조회를 우선 구현하고, 화면 장식과 세부 필터는 후순위로 조정 |

## 2. 완성본 구현 계획

### 구현 목표

MVP의 공유 플래너·앨범을 안정화하고, 여행 지도·영수증 정산을 추가합니다.

최종적으로 계획한 장소, 여행 사진과 지출을 장소 단위로 연결하여, 실제로 들른 곳과 계획만 한 곳을 지도에서 구분해 조회할 수 있도록 합니다.

### 최종 구현 범위

| 기능 영역 | 완성본 구현 내용 | MVP 이후 추가·보완 사항 |
|---|---|---|
| 공유 플래너 | 날짜별 일정 작성·편집 및 장소·예상 비용 관리 | 입력 검증, 여행 기간 변경 시 일정 보호 및 사용성 개선 |
| AI 일정 추천 | 여행 조건에 따른 추천 일정과 장소 검색 대조 | 출력 형식 검증, 실패 대응, 결과 재사용 및 추천 품질 평가 |
| 공유 앨범 | 사진 업로드·조회 및 날짜별·장소별·업로더별 보기 | 필터와 조회 편의성 개선, 장소에 연결되지 않은 사진 표시 |
| 여행 지도 | 사진·지출이 연결된 들른 곳과 일정에만 있는 계획만 한 곳을 핀으로 구분 | 날짜·멤버 필터, 핀을 선택하면 연결된 일정·사진·지출을 함께 조회 |
| 영수증 분석 | Gemini API로 상호·품목·수량·금액·총액 추출 | 원본 대조·수정, 분석 실패 시 수동 지출 입력, 상호 검색으로 지출 장소 지정 |
| 항목별 분담 | 지출의 기본 분담 대상 지정 및 품목별 예외 수정 | 균등 분담과 원 단위 나머지 배분 |
| 합계·누락 검사 | 품목 합계·총액·결제자·분담 대상 확인 | 확인 조건을 만족한 지출만 정산에 반영 |
| 정산 및 계산 근거 | 개인별 결제액·부담액·잔액·송금 제안 제공 | 부담액에서 원본 지출과 품목까지 조회 |
| 송금 기록·재정산 | 송금 완료·일부 송금 기록 | 지출 수정 시 기존 송금을 반영하여 남은 금액 갱신 |
| 통합 검증 | 실제 기기와 배포 서버에서 전체 흐름 확인 | 권한·계산 정확성·AI 오류 대응·사용성 평가 |

### 최종 단계 RISK 관리 계획

| 위험요소 | 대응 계획 |
|---|---|
| 위치정보 수집에 따른 법적 의무·스토어 위치 권한 심사 | 이동경로를 기록하지 않고, 앱은 위치 권한을 쓰지 않으며, 서버는 사람의 위치 좌표를 받거나 저장하지 않음 |
| 사진의 EXIF 정보 누락 또는 잘못된 장소 연결 | 자동 연결 결과 수정 지원, 위치 정보가 없으면 촬영 날짜에 연결하고 장소 검색으로 직접 연결 |
| 영수증 오인식 | 추출 결과를 바로 확정하지 않고 사용자 확인·수정과 합계 검사 후 정산에 반영 |
| 정산·재정산 계산 오류 | 혼합 지출·나머지 배분·복수 결제자·일부 송금 후 변경 사례를 정답과 비교 |
| 외부 API 비용·사용량 증가 | 호출 제한, 분석·추천 결과 재사용, 사용량 확인 |
| 기능 확장에 따른 일정 지연 | 플래너·앨범과 장소별 기록 연결을 우선 완성하고 지도·영수증 분석을 후순위로 조정 |
